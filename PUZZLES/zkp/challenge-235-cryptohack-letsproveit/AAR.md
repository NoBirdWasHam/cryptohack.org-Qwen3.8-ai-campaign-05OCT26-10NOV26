## The vulnerability
Despite the "Sigma protocol" framing, this is a **Schnorr/Fiat-Shamir proof of knowledge of the flag as a discrete log**: `y = 2^FLAG mod p`, `t = 2^v`, `c = sha3_256(t^y^g)^2`, `r = (v - c·FLAG) mod (p-1)`. Two flaws combine:

1. **PRNG-seed oracle:** `p` is generated by `getPrime()` from `random.Random(nonce + seed)`, and the `refresh` option lets the *client* choose `seed` (the nonce is printed in `before_input`). So we know exactly which PRNG stream the server's `p` comes from.
2. **No modular wraparound:** `c ≈ 2^512` (square of a 256-bit hash), `FLAG ≈ 2^311`, so `c·FLAG < p-1` (1024-bit) and `v < 2^512`. Hence `r = p-1 + v - c·FLAG` holds **over the integers**, giving `c·FLAG = (p-1-r) + v` with `v ∈ [0, 2^512)`.

## The attack
1. `get_proof` (unlocks `refresh`), then `refresh` with our own 8-byte seed, then `get_proof` → `(t, r, y)` with `p` from our seed.
2. Replicate `p` locally: replay `Random(nonce+seed)` through the same `getrandbits(1024)|1` + `isPrime(randfunc=λx→R.getrandbits(x))` loop.
3. `FLAG ∈ {(p-1-r)//c + d}` — window width `2^512/c` (≈2–256; **must be computed dynamically**, a fixed small window fails ~25% of instances because `c`'s bit-length varies with the hash).
4. Verify the candidate with `pow(2, S, p) == y`, then decode: `S` is 39 bytes = `"crypto{" + (middle31 XOR nonce) + "}"` with one random non-printable byte inserted at a random index; un-XOR the nonce, try removing each byte, keep the printable `crypto{...}` match.

## Key numbers
- p: 1021–1024 bits; c: 505–512 bits; FLAG: 311 bits; v: 512 bits; 2 protocol turns used of 12.

## Learning points
- A client-controlled PRNG seed is a full source of randomness for anything derived from it — here the *challenge prime*.
- Always compare `c·secret` against the group order: when `c·secret < p-1`, the Schnorr response leaks the secret up to the width of `v`'s range — the hidden number problem (HNP) in one line, hence the flag text.
- Bit-lengths of hash-derived challenges vary; derive search windows from the actual `c`, never from an assumed 2^512.

## Limitations
- First local runs failed because of a fixed `d in 0..10` window (evidence: debug showed `q-FLAG` down to -33); fixed with dynamic width, then 10/10 offline.
- `isPrime` PRNG-replication is PyCryptodome-version-sensitive in principle; offline 8/8 primes matched (`pow(2,FLAG,p)==y`) and the live server matched on the first try, so the drafted candidate-prime-walk fallback was not needed.
