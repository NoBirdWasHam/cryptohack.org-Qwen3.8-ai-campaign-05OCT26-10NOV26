## procedure — extracted from AAR section "The vulnerability" [OBSERVED text; evidence tag applies to its source, not each claim]
Despite the "Sigma protocol" framing, this is a **Schnorr/Fiat-Shamir proof of knowledge of the flag as a discrete log**: `y = 2^FLAG mod p`, `t = 2^v`, `c = sha3_256(t^y^g)^2`, `r = (v - c·FLAG) mod (p-1)`. Two flaws combine:

1. **PRNG-seed oracle:** `p` is generated by `getPrime()` from `random.Random(nonce + seed)`, and the `refresh` option lets the *client* choose `seed` (the nonce is printed in `before_input`). So we know exactly which PRNG stream the server's `p` comes from.
2. **No modular wraparound:** `c ≈ 2^512` (square of a 256-bit hash), `FLAG ≈ 2^311`, so `c·FLAG < p-1` (1024-bit) and `v < 2^512`. Hence `r = p-1 + v - c·FLAG` holds **over the integers**, giving `c·FLAG = (p-1-r) + v` with `v ∈ [0, 2^512)`.

## reusable-rules
- A client-controlled PRNG seed is a full source of randomness for anything derived from it — here the *challenge prime*.
- Always compare `c·secret` against the group order: when `c·secret < p-1`, the Schnorr response leaks the secret up to the width of `v`'s range — the hidden number problem (HNP) in one line, hence the flag text.
- Bit-lengths of hash-derived challenges vary; derive search windows from the actual `c`, never from an assumed 2^512.
