# ECDSA nonces from LCGs — attack-family map when recurrence modulus ≠ curve order

## When to Use
Challenge gives ECDSA signatures whose nonces come from an LCG/quadratic generator, and
either the recurrence modulus differs from the curve order, is unknown, or plain mod-order
lattice attacks misprice. Also when a writeup mentions 'LCG nonce' + 'unknown prime'.

Setup signature: signatures (r,s) on known msgs; nonces generated by affine/quadratic LCG
with secret params, possibly under modulus p ≠ curve order n (e.g. p = getPrime(311) with
secp256k1 n ≈ 2^256). Always check FIRST which modulus the recurrence lives in.

## Core identity (every attack starts here)
k_i ≡ z_i·s_i⁻¹ + (r_i·s_i⁻¹)·d (mod n)   — k_i is a known LINEAR form in d mod n.
If nonces can exceed n: k_i = (that form) + n·t_i with fold t_i < 2^(bits(k)−bits(n)).
Folded view ⇒ r_i = x([k_i]G) leaks nothing extra ([k]G depends on k mod n only).
(If curve field prime P > n and chall does NOT reduce r mod n, r carries 1 extra bit per sig.)

## Family 1 — recurrence holds mod n (Macchetti, eprint 2023/305; closed-form, instant)
Finite-difference kills secret coefficients: for affine LCG, define k_{i,j} := k_i−k_j;
minors k_{1,2}²−k_{2,3}k_{0,1} ≡ 0 (mod n) are recurrence-free; substitute the linear form
k_{i,j} = ((r_i/s_i − r_j/s_j)d + (z_i/s_i − z_j/s_j)) → polynomial in d of degree 2 (quad
generator N=5: deg 4 via eq-21 invariant; dpoly recursion in the paper for higher).
Roots via gcd with x^n−x then Tonelli (CAREFUL: t=n^Q with Q the ODD part, M=S the
2-valuation — classic swap bug). Verify each root by an independent oracle. 4 sigs suffice.

## Family 2 — recurrence mod p KNOWN, truncated states observed (FHKLS / C-S)
vdsn crypto-attacks attacks/lcg/truncated_parameter_recovery.py = reference impl.
Known modulus: lattice on top-bit unknowns, works when hidden fraction < ~1/2.
Unknown p,a (C-S): polynomial-resultant+gcd step needs chunk n+t with t≈1/α,
n≈√(2αtk), α = visible/total bits. ALWAYS compute the chunk requirement first — it
silently exceeds CTF sample counts (α=256/311 → chunk ≈26 > 17 sigs).

## Family 3 — recurrence mod UNKNOWN p AND view folded through d (HITCON-eclcg class)
Measured geometry (planted full-fidelity, 311-bit p, 256-bit n, 17 sigs):
- differences Δ_i = (α_i d+β_i mod n) + n·v_i, |v|≈2^55; minors M_i = c·p with |c|~2^309
  (not small) — gcd-of-minors recovers p GIVEN d, nothing else.
- Decomposition M_i = A_i(d) + n·L_i(d,v) + n²·Q_i(v); heights ≈ 509/568/619 b.
- Linearization over monomials(d,v)+cofactor slots: margin ≈ −200 b (no solution regime).
- Resultant elimination adds ~(deg+3)·log2(n·H) dust per depth; scale-invariant wall
  ≈ 4.5–4.8 × p_bits. Coppersmith unreachable: d ≥ p^{1/deg} at every usable deg.
⇒ Required (not yet known) breakthrough: an identity where d appears ONLY multiplied by
fold-sized factors (d·v ~ 2^312) and p only as a shared gcd factor, never as coordinate.
DO NOT re-price (measured dead): linearizations over (d,v) with/without cofactors;
resultants of pair-eliminated congruences; Stern/C-S on folded views; Macchetti mod-n on
folded data (run it anyway once — 2 minutes; negative = model confirmation; SELF-TEST the
root-finder on a planted mod-n instance first, and check the recurrence-mod-n wiring —
some authors genuinely wire the LCG mod n).

### SOLVED route (author solve2.py port, verified 2026-11-08; HITCON ECLCG closed)
Pipeline (all steps measured):
1. v1_i = z_i/s_i − z_{i+1}/s_{i+1}, v2_i = r_i/s_i − r_{i+1}/s_{i+1} mod n; k_i−k_{i+1} ≡ v1_i + v2_i·d (mod n).
2. find_ortho_fp(n, v1, v2) -> ortho; find_ortho_fp(n, *ortho) -> ortho2; diff_k ∈ rowspace(ortho2).
3. reduce_mod_p(p2=2^255−19, [ortho2.T[:-1] | ortho2.T[1:]]): echelon over GF(p2), stack p2·I rows, reduce;
   interleave front/back windows of first n−4 rows -> L2; mu = dim-1 kernel generator; diff_k = mu·ortho2 (±).
4. dk=diff_k[0]: solve {s0(k1+dk)=z0+r0 d; s1 k1=z1+r1 d} linearly mod n -> d; verify via EC r-check on ALL sigs;
   flip sign dk if invalid; CTR key = sha256(str(d)).
find_ortho_fp(M, vecs) exact semantics (sage): rows [vecs_j[i]·M | e_i] for all i PLUS nv rows M·I_nv
(block_matrix SCALAR BLOCKS ARE SCALAR MATRICES — per-family INDEPENDENT quotients), cols 0..nv−1 ×= M;
reduce; keep rows whose first nv coords are EXACTLY zero. The true diff_k passes this filter.
CRITICAL PORT FACTS:
- Reduction choice is load-bearing: keeganryan/flatter yields exact-zero-prefix rows; fpylll LLL(delta .99) did NOT
  on this instance. flatter builds on Windows/MSYS2: g++ -O2 -std=c++17 -fopenmp -include cstdint with
  -Iinclude -Iinclude/flatter -Isrc, exclude fplll_impl/eigen_impl, dlarf_/dlarfg_ shim compiled with gcc
  (g++ mangles .c!), mpfr/mpz objects linked first (dup is_upper_triangular), -Wl,--allow-multiple-definition.
  Persisted binary: <toolroot>/flatter/flatter.exe (toolroot: windows-crypto-toolchain); CLI: stdin "[[a b][c d]]" -> stdout matrix.
- sage matrix[:-1]/[1:] slice ROWS not columns; right_kernel_matrix is HNF-saturated (sympy nullspace fine ONLY for
  dim-1 kernels with small generator — else non-saturated rational artifacts).
- solve3.py's compact variant (delta_k via shared-row kernel) resisted porting; solve2.py structure is the one to port.
- ALWAYS plant a synthetic instance FIRST (own d, own LCG, full pipeline incl. EC r-check gate): it is the only gate
  that exposed all three semantics bugs after several "looks right" passes.

## General cautions
- fastecdsa/ecdsa libs reduce the nonce mod n silently — model r,s from k mod n.
- 1-bit-per-sig leak from unreduced r (field prime > order): usually unusable; note it.
- HNP sample rule governs partial-view attempts: ~bits(d)/leaked-bits signatures needed.
- Verify candidate keys by independent oracle (pubkey multiplication / AES decrypt shape),
  never by bitlength.
